# PilgrimAI

PilgrimAI helps pilgrims plan temple visits, darshan, travel, stays, and rituals. NestJS is the application server and serves the React frontend from `public/`; FastAPI is the worker between NestJS and the RAG agent.

## Architecture

```text
React (served by NestJS)  ──>  NestJS API  ──>  FastAPI worker  ──>  RAG agent
                    │                                  │
                    └── Google OAuth + Supabase ───────┘
```

The browser only communicates with NestJS. NestJS validates incoming chat requests and forwards them to the FastAPI worker. The worker is the middle layer for the RAG agent and retrieval logic. NestJS persists authenticated Google profiles in Supabase using a server-only service-role key.

## Project layout

```text
src/                 NestJS API gateway and Google OAuth routes
worker/              FastAPI middle layer between NestJS and the RAG agent
public/              React frontend source and static assets, served by NestJS
.env.example         Central configuration for React, NestJS, FastAPI, and RAG
```

## Prerequisites

- Node.js 20 or later
- A running FastAPI RAG service (default: `http://localhost:8000`)
- A Supabase project
- A Google OAuth 2.0 web client

## Run locally

Create the shared configuration once at the project root:

```bash
copy .env.example .env
```

Install dependencies and start the NestJS application. This also bundles the React files in `public/`:

```bash
npm install
npm run dev
```

In a second terminal, start the FastAPI worker:

```bash
cd worker
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000 --env-file ../.env
```

NestJS serves both the React app and API on `http://localhost:3000`; the worker runs on `http://localhost:8000`. If either URL changes, update `FRONTEND_URL`, `PUBLIC_API_URL`, `FASTAPI_URL`, and `RAG_AGENT_URL` as appropriate.

## Google sign-in

The frontend's **Continue with Google** button opens `GET /auth/google` on NestJS. Configure these values in the root `.env`:

```dotenv
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret
PUBLIC_API_URL=http://localhost:3000
FRONTEND_URL=http://localhost:3000
SESSION_SECRET=a-long-random-secret
```

In Google Cloud Console, add this authorised redirect URI:

```text
http://localhost:3000/auth/google/callback
```

NestJS receives the verified Google profile, upserts it to Supabase, and issues a seven-day HTTP-only session cookie. Create the profile table before first sign-in:

```sql
create table if not exists public.profiles (
  id bigint generated by default as identity primary key,
  google_id text unique not null,
  email text not null,
  full_name text not null,
  avatar_url text,
  updated_at timestamptz not null default now()
);
```

Set `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` in the root `.env`. Vite exposes only variables prefixed with `VITE_`, so the service-role key stays server-side. Never commit `.env`.

## API contract

React sends chat requests to NestJS:

```http
POST /api/chat
Content-Type: application/json

{ "query": "Darshan timings at Yadadri", "temple": "yadadri", "language": "en" }
```

NestJS forwards the same payload to `FASTAPI_URL/api/chat` (the worker, default `http://localhost:8000/api/chat`). The worker then calls `RAG_AGENT_URL/api/chat` and returns its response. The RAG agent should return a JSON object containing at least `reply`.
